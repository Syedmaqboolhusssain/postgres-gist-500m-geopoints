======================================================================
 Are the answers even right? (a check the tutorial skips)
======================================================================
The points are uniform over the whole globe: 360 deg of longitude by 180
of latitude = 64800 square degrees. So the expected number of hits for any
shape is simply  N * area / 64800.  If the measured counts land near these
numbers, the data really is uniform and the index really is returning
everything it should -- a fast query that quietly returns too few rows is
not a win. This also explains why the tutorial's circle and polygon queries
return zero rows at 10M: the expected counts there are 0.2 and 1.2.

WITH n AS (SELECT count(*)::numeric AS rows FROM locations),
shapes(shape, area_deg2) AS (
    VALUES ('box   (0.4 x 0.3 deg)',      0.4 * 0.3),
           ('circle (r = 0.02 deg)',      pi() * 0.02 * 0.02),
           ('polygon (0.08 x 0.10 deg)',  0.08 * 0.10)
)
SELECT shape,
       round(area_deg2::numeric, 6)                      AS area_deg2,
       round(n.rows * area_deg2::numeric / 64800, 1)     AS expected_rows
FROM shapes, n;
           shape           | area_deg2 | expected_rows 
---------------------------+-----------+---------------
 box   (0.4 x 0.3 deg)     |  0.120000 |         925.9
 circle (r = 0.02 deg)     |  0.001257 |           9.7
 polygon (0.08 x 0.10 deg) |  0.008000 |          61.7
(3 rows)
